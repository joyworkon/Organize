# Organize：可直接复制给其他 Agent 的提示词

任务详情见 [长期计划](long-term-agent-plan-2026-09-11.md)。使用方式：给一个有写权限的 Agent 发送模板 1；其他 Agent 可发送模板 3/4/5。不要向多个 Agent 同时发送模板 1 并让它们操作同一项目目录。

所有提示词都要求执行者先核实最新事实。2026-09-11 的基线为 `84a6239`、迁移 075、备份 v5、147 个 Vitest 文件/1,095 条测试；这些不是未来永远正确的固定断言。

## 1. 推荐：工程 Agent 连续接力

```text
请继续建设 Organize 项目，路径 /Users/k/Documents/ZCode/Organize。

先读 AGENTS.md、docs/long-term-agent-plan-2026-09-11.md、docs/agent-prompts-2026-09-11.md，以及存在时的 docs/agent-workboard.md。旧 ROADMAP、PROGRESS、BLOCKED、docs/handoff/execution-log.md 用于核对历史，不能按旧任务表重复实施。先核实当前 Git 状态和任务证据。

本轮按 A01→A02→A03→A04→A05 顺序执行，每次只做依赖满足的一张卡。已被其他 Agent 完成的卡核实证据后跳过；外部条件阻塞时记清并转到 B01、B02 或 C01 中依赖已满足的卡。不要直接开展 E 类候选功能。目标是交付可验收结果，不是机械耗尽 Token。

只有确认当前 checkout 没有其他写入 Agent 时才改代码；有人正在写时，先只读检查并输出仓库外报告。不要 stash、覆盖、删除他人的修改。取得独占后，按 AGENTS.md 从最新 master 创建 feat/fix/docs/chore 分支；一个任务一个 PR，CI 全绿后依照仓库单人项目规则 squash 合并、清理该任务分支、同步 master，再做下一张。禁止直接 push/force push master。GitHub 权限不足则保留提交和清楚的交接，不伪称合并。

先复现和确认当前实现，再动代码。数据/权限变更同步考虑迁移、RLS+GRANT、mock、备份v5及旧格式、垃圾箱、离线和共享。复用 collectReadingItem、note-save-session、safeAIRequest，不创建第二套业务管线。纯重构保留现有行为和旧正文 JSON 兼容。

按卡运行 web typecheck、Vitest、lint、build 和相关 E2E；数据库用隔离测试环境跑 pgTAP，协作跑 collab-server 检查和 COLLAB_E2E 真服务验证。不要通过跳过、删测试、弱化断言或假数据成功制造绿灯。不能把 mock 测试当作真实后端或真机验收。纯文档不需全套业务测试。

你可以完成这些卡要求的本地开发、测试、PR 与仓库允许的合并；不要因此购买服务、公开发布安装包、修改生产数据库、清理用户数据或发送邀请邮件给真实用户。需要外部条件时把代码、配置模板和验收步骤做完整，最后列出准确阻塞项。

每卡结束更新账本（A01 创建），记录：基线、发现、修改、测试命令和结果、PR/commit、未验证项、下一卡。无法完成验证时标“待验证”，不要标完成。长任务按可审查的小步骤保存进度，不让下一位重新调查。

最终报告：实际完成哪些卡、哪些测试真正运行、哪些问题仍存在、下一位应从哪里继续。请直接开始工作。
```

## 2. 指定任意一张任务卡

复制后只替换任务 ID。例如把 `B01` 换成 `B03`。

```text
请执行 /Users/k/Documents/ZCode/Organize/docs/long-term-agent-plan-2026-09-11.md 中的 B01 卡。

先读 AGENTS.md、计划全文执行规则和最新 docs/agent-workboard.md。确认此卡仍未完成、依赖满足、你独占当前 checkout；没有独占权就只读分析，不切分支不改文件。不要重复旧 R/D 已完成的工作。

按此卡范围做完复现、实现、必要验证与交接。若为 L 级卡，先写接口/状态/数据兼容/回退设计，再拆成串行的小 PR，不为压成一个 PR 降低验收。按仓库规则同步 master、建特性分支、提交 PR，CI 全绿后按已有仓库授权合并；没有 GitHub 权限则明确留交接。

使用 corepack pnpm。数据库测试使用隔离环境，不修改 .env.local、不重置用户库；新持久化行为核对 RLS/GRANT、mock、备份、垃圾箱、离线及共享。不能通过 skip 或假成功交付。缺硬件/凭据时完成其余可执行部分并标“待验证/阻塞”，不要把文档里的历史通过记录当成本次通过。

每个完成项给出源码/测试/commit 证据。最终给出完成状态、验证结果、未覆盖范围与下一步，不顺手扩展到其他卡或公开部署。
```

## 3. 审查 Agent：可与工程工作并行的只读任务

```text
请只读审查 Organize，路径 /Users/k/Documents/ZCode/Organize。先读 AGENTS.md 和 docs/long-term-agent-plan-2026-09-11.md。

重点检查 A02 Service Worker、A05 协作身份刷新/撤权、B01 备份恢复的现有实现与测试缺口。此次只做源码与测试逻辑审查，不执行会写缓存/构建目录/数据库的测试，不切换分支，不 stash，不修改项目文件，不启动共享服务。其他 Agent 可能正在写代码：记录开始和结束 commit；工作树变化影响结论时注明，不能把混合版本当稳定基线。

先确认旧问题是否已经修复。每条发现必须包含：严重度、准确文件/行号、触发条件、用户可见后果、现有防护为什么不足、最小验证办法和建议修复边界。未经复现的推断标“待验证”，不能说成已发生事故。不要为了凑数量提纯风格意见，不重新要求实现已完成的 R01–R11。

把报告写入 /tmp/organize-review-<本次唯一标识>/review.md（目录与工程 checkout 分离），最后返回绝对路径。没有发现可行动问题也直接说明，并列审查局限。不要直接修改 PROGRESS/BLOCKED 或替工程 Agent 标完成。
```

## 4. 设计 Agent：让以后的改版更容易

```text
请为 Organize 执行 C01 界面地图，并准备 C06 功能入口整合提案。仓库 /Users/k/Documents/ZCode/Organize。先读 AGENTS.md、docs/long-term-agent-plan-2026-09-11.md 和现有布局/导航/主题代码，特别核对最近移动导航变化。旧 docs/handoff/02-ui-redesign-plan.md 已大部分实施，不能再从头执行它。

这次是设计和只读盘点，成果放 /tmp/organize-design-<本次唯一标识>/，不切换分支、不改业务源码、不启动或占用现有开发服务器。可以在独立输出目录制作可打开的 HTML 交互预览。

交付：1）当前功能→页面/菜单/快捷键/角色入口地图；2）主题 token、shell 和页面组件的修改指引；3）工作台/笔记/任务与经验/速记/图谱如何整合入口的方案；4）桌面和手机可点击预览；5）未来正式接入的逐页小任务和回退方法。

保持旧 URL、历史、导出、附件、分享、冲突、本机保存失败、页面偏好等能力可找到。预览用演示数据且标注，不创建假后端成功。不要删除表、改保存协议、重写编辑器或引入第二套 UI 组件库。界面简化优先减少重复入口，不靠删能力实现。

用实际截图/交互验证输出，若没有浏览器验证能力就明确未验证。最后给方案与文件路径，等待用户确定方向后再安排业务接入；不要把预览当成正式改版完成。
```

```text

仓库 /Users/k/Documents/ZCode/Organize。先读 AGENTS.md、docs/long-term-agent-plan-2026-09-11.md、docs/product-experience-audit-2026-09-06.md、docs/macos-notch-compatibility-review-2026-09-06.md 及后续修复代码。不要重复报告已修复项。

默认只读，不切分支不改项目文件，不重启他人服务器；在 /tmp/organize-device-checks-<本次唯一标识>/ 输出逐步验收表。每个案例含前提、设备/系统/版本、输入数据、操作、预期、实际、截图位置和失败后定位入口。覆盖中文输入、键盘/安全区、旋转、草稿恢复、分享回跳、多屏缩放、热插拔、睡眠、跨窗口通知、安装更新和深链。

最后给最优先的 10 分钟人工验收路径、完整矩阵、已测证据和剩余依赖。
```

## 6. 剩余额度较少时的收尾提示词

```text
请先保存你当前 Organize 任务的真实状态，不开启新的大型重构或迁移。

检查 git status、当前卡和已执行测试。完成本卡剩余的小范围验证/修复；把未解决问题、精确复现步骤、修改文件、命令结果、分支/commit/PR、正在运行的本任务进程以及下一步写成交接。不要覆盖其他 Agent 的修改，不把未测写为通过，不输出密钥。

若已有一张卡完整通过验收，按仓库规则提交并完成允许的 PR 流程；若工作尚不满足完成定义，保留可审查提交并标明 WIP/待验证。用剩余额度检查一个高风险边界，比另起半成品更有价值。
```

## 7. 接手上一个 Agent 的提示词

```text
请接手 Organize 上一个 Agent 的工作。先读 AGENTS.md、docs/long-term-agent-plan-2026-09-11.md、docs/agent-workboard.md（如存在）和上一位的交接报告。

第一步只读核实 git status、当前分支、最新 commit、PR 状态和在途进程，不立即 checkout master 或 stash。确认没有仍在工作的写入 Agent，再决定继续当前卡或开始下一卡。对未完成修改先理解来源，不重置、不重复实现。

把上次“已实现/待验证/阻塞”分别核对。优先完成在途卡，运行缺失的真实验证；有证据证明完成后更新账本。之后依长期计划领取最早一张依赖满足的任务。保留已完成的业务语义、数据库迁移和用户数据，沿用一张卡一个 PR、一次一条实现分支的规则。

最后报告哪些结论由本次重新验证、哪些仍仅来自历史交接，以及下一位准确的起点。
```

## 8. 每张卡的交接格式

```markdown
### 卡 ID / 标题
- 状态：就绪 / 进行中 / 待验证 / 阻塞 / 完成 / 取消
- 基线与当前：commit、分支、工作区是否干净
- 目标与实际范围：
- 原问题与复现证据：
- 修改与行为变化：
- 验证：命令、环境、退出结果、关键断言、产物路径
- 未运行/未覆盖：
- 数据兼容与回退：
- PR/提交：
- 外部依赖：只列配置名称，不含秘密值
- 本任务在途进程和是否应保留：
- 下一位第一步：
```

提示词里的工程授权不代表所有角色都能同时写代码；用户若仅派发只读/设计模板，执行者须保持该范围。计划会演进：每轮先核实，不照编号机械开工。
