# ADR 0001: 任务 ↔ 笔记待办双向链接

- 状态: 已接受 (G0 协议冻结)
- 日期: 2026-07-31
- 阶段: G0(协议冻结，仅文档)

## 背景

Organize 当前有两套互相独立的"待办"概念:
1. **全局任务** — `tasks` 表行，在 `/tasks` 页管理，有 status/priority/due_date；`tasks.note_id` 是 1:1 单向指向整篇笔记的导航链接。
2. **笔记待办** — 编辑器里官方 `taskItem` 节点(`checked: boolean` + 内联文本)，存在 `notes.content` jsonb 里，**与 tasks 表零连接**。

两者无 ID 关联、无同步。用户在笔记里勾的待办不会进任务页，任务页改的状态也不回笔记。

## 决策

建立**任务为唯一事实源(canonical)、笔记 TaskItem 为引用/显示缓存**的双向链接:

1. **tasks 表是事实源**。笔记里的 TaskItem 节点增加 `taskId` 属性，指向 tasks 行；TaskItem 本身只是带 taskId 的引用+本地显示态。
2. **task_item_refs 表**记录引用关系(user_id, task_id, note_id, block_id)，唯一 (note_id, block_id)。一个任务可被多个笔记块引用。
3. **双向同步只含标题 + 完成状态**。截止时间/优先级只在任务页编辑，笔记只读展示。
4. **历史无 taskId 的 taskItem 不自动任务化**；仅当用户真实改字或勾选时才激活(转成任务)。
5. **系统事务(hydrate/版本恢复/备份恢复/远端同步)不得激活 legacy、不得生成任务 mutation、不得进 Undo 栈**。
6. **同步入口**：不依赖改写全部 6 条 notes.content 写入口，而是通过**原子保存 RPC**(G1)统一拦截显式保存；版本恢复/备份恢复等系统路径在 G2/G3 显式处理为"只恢复布局/引用，不回滚 canonical 状态"。

## 取舍

- **数据正确/安全 > 旧数据兼容 > 交互完整 > 速度**。`tasks` 是事实源意味着：快照(版本/备份)里的 TaskItem 即使带回 taskId，也不得覆盖 canonical task 的状态——只能恢复"这块引用了哪个任务"的布局关系。
- **复制绑定块 = 同任务新引用**；纯文本/外部粘贴 = 新任务。避免静默合并两个不同任务。
- 受管理(reference_managed)任务最后一个活动引用消失 → 进可撤销垃圾箱；独立任务允许零引用。
- 图谱、完整离线、原生端、多人协作、语义 AI 不在本范围(后续路线图)。
