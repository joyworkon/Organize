# 构思画布：交给执行 Agent 的提示词

```text
请在 /Users/k/Documents/ZCode/Organize 实现新功能「构思画布」。这次任务是实际开发，不是继续写规划。

先读当前 AGENTS.md，再完整阅读 docs/idea-canvas-plan.md。该文件是本任务的产品规格、交互合同、工程边界和验收清单。只执行该文件的首版 C01–C04，不顺手执行历史总路线图中的其他任务。

目标：在无限画布中，让用户通过输入内容和加号快速搭建海报、内容卡片及演示页面的原型。入口在左侧「笔记」下方，与笔记同级；显示「构思画布」，列表 /canvas，详情 /canvas/[id]。

不能丢掉的原始交互：
1. 双击画布空白处即创建固定初始宽度的自动版面和标题模块，立即输入。版面内后续行宽度保持一致。
2. Enter 在当前整个分区下方新增通栏。两列以上也要跨整排；Shift+Enter 才是模块内换行。中文输入法候选确认不能误建块。
3. 左右加号在当前分区添加列，已有列自适应分配宽度，不撑宽上方标题。
4. 模块底部的局部加号只在本列添加下一块。左侧两块等高，右侧只有一块时自动跨两层。它和「新增通栏」必须是不同操作、不同预览。
5. 图片保持原始比例，图文容器自动等高。实现规格中的一文一图智能列宽、等分和手动比例；默认完整显示，可切换裁切铺满，禁止非同比例拉伸图片。
6. 提供绝对定位的自由文本/图片容器，独立于自动版面。

先冻结并测试布局命令与尺寸规则，再实现交互，随后完成真实数据闭环与集成。首版必须含保存、草稿恢复、冲突保护、图片上传、mock、撤销重做、软删除/垃圾箱及全局备份恢复，不能只交静态 UI 或仅 localStorage 演示。

技术约束：
- 独立 CanvasDocument 模型和 canvas_documents 表，使用稳定 ID、schemaVersion 与 revision，不修改 notes.content 的语义。
- 布局按 Board → Section → Column → Block 建模；首版左右加号操作整列，任意模块内部的递归横向嵌套留待后续。
- React DOM + CSS 布局及工作区坐标变换优先；复用现有组件、主题与 Zustand。布局算法和数据命令放 lib/canvas，UI 放 components/canvas。不要把逻辑全部写进 page.tsx。
- 先定宽，再测自然高度，最后拉伸；不要读取已拉伸高度反馈到宽度计算，避免布局抖动。
- 服务端原子 revision 检查，保存串行且防旧响应覆盖。副作用不放入 setState 更新器/reducer。草稿、资源和异步回调按用户/文档隔离。
- 新表启用 RLS 并 GRANT；迁移编号取当前最大值递增。备份版本兼容旧数据，图片打包恢复与垃圾箱 RPC 一并接通。
- 新增 API 必须补 mock shim，不能假设服务端会访问浏览器 mockDb。上传失败不可把临时 blob URL 标为已保存。
- 核对 sidebar.tsx 的辅助组固定插入索引，改用语义锚点，避免新增入口打乱收藏夹/协作组。手机保持五个底栏入口，从抽屉进入画布，首版只读预览。
- 不实现本规格明确放到后续的 PNG/PDF 导出、PPTX、AI、实时协作、复杂嵌套和插件市场，也不要显示无效占位按钮。

开始前检查 git status。本次规划可能仍是 docs/idea-canvas-plan 分支上的本地未提交文档；先读取并保护它们，用仅包含规划文件的提交或可恢复暂存处理，不能删掉、覆盖或遗漏。然后按 AGENTS.md 同步最新 master，建立一条 feat/ 或 codex/ 功能分支，再带入必要的规划文档。不同时在多条实现分支工作，不改无关文件。

按方案 C01 → C02 → C03 → C04 持续完成，不在阶段间反复请求普通实现决策。出现会改变原始交互、造成不兼容数据迁移或需要生产权限的真实阻塞时再说明问题。

验收：逐条核对规格 A01–A17，用真实浏览器确认布局、焦点、缩放、中文输入和主题；用两个用户/两个标签验证隔离与冲突；验证备份往返及垃圾箱恢复。运行 pnpm --filter @organize/web typecheck、pnpm --filter @organize/web test，以及新增的画布 E2E。只能验证 mock 的部分必须明确标记，不能宣称数据库已验证。

交付：实现代码、迁移、必要回归测试、使用说明、代表性截图/录屏、A01–A17 验收结果和未验证事项。完成后提交功能分支、push 并创建 PR，附测试结果与迁移说明，将 PR 链接交给我；本次不自动合并或部署生产。
```
