# 刘海激发器（Notch Trigger）规划 —— 草案 v1，原型讨论用

> 状态: 规划（未排期、未实现）。本文是原型讨论的输入，实现前须先过一轮
> 形态与交互确认；具体尺寸 / 动画 / 展开时机见 §6 待讨论清单。
> 前置: 依赖 ADR 0004 的托盘常驻基建（已落地）。

## 1. 目标

在 MacBook 顶部刘海位置放一个常驻「激发器」：鼠标移上去弹出**速记面板**
（flomo 式，Enter 保存进应用），面板内同时提供其他功能的快速入口与设置
入口。本质是把「打开应用 → 找到速记页 → 输入」压缩成「随手一碰 → 输入 →
Enter」，捕获碎片想法的路径缩到最短。

## 2. 形态选项

| 选项 | 形态 | 优点 | 缺点 |
|---|---|---|---|
| **A（主推）** | 刘海延伸 pill：一个贴着刘海下缘的深色小胶囊（模拟刘海加宽），hover 展开面板 | 形态最克制、最有「系统级」感；不占菜单栏 | 无刘海 Mac 退化为顶部悬浮 pill（需处理观感）；全屏应用遮挡时不可见 |
| B | 普通菜单栏 NSStatusItem 图标，点击展开面板 | 实现最简单、全屏也可见 | 无「hover 即弹」的惊喜感，菜单栏图标 another one |
| C | 纯全局快捷键（如 ⌥Space）唤出面板 | 零视觉占用、键盘流 | 无视觉暗示，发现性差 |

选项 A 为主、C 为兜底（全局快捷键同一面板，hover 不便时键盘唤出）是规划
倾向；B 不做。

## 3. 技术草案（Tauri v2 / macOS）

```
┌─ screen top ────────────────────────────────┐
│                  [刘海区]                    │
│            ┌─trigger 180×28─┐               │  ← 透明无边框窗口，深色胶囊
│            └──(mouseenter)──┘                │
│         ┌─panel 360×480─┐                    │  ← 展开层：速记输入 + 入口
│         │ #会议 #想法       │                  │
│         │ [textarea]        │                  │
│         │ Enter 保存           │               │
│         ├──────────────┤                    │
│         │ ⚡速记 📚稍后读 📝笔记 ✅待办 ⚙设置│      │
│         └──────────────┘                    │
└──────────────────────────────────────────────┘
```

- **两个 Tauri 窗口，Rust 侧管理**：
  - `notch-trigger`：`transparent + decorations(false) + alwaysOnTop +
    skipTaskbar + visibleOnAllWorkspaces`，尺寸约 180×28，`primary_monitor()`
    顶部水平居中定位；内容为模拟刘海的深色胶囊（CSS，贴近刘海色 #1e1e1e）。
  - `notch-panel`：约 360×480，与 trigger 同锚点，默认 `visible(false)`。
    hover 展开、`blur`（失焦）收起。
- **定位与监看**：启动与显示器变更时重算位置；面板展开期间锁定位置。
- **保存链路（复用零新后端）**：panel 窗口加载同一 web origin，登录态
  cookie 在各窗口间共享（同 WKWebsiteDataStore）；输入 Enter →
  `POST /api/memos { content }`（服务端 `parseMemoTags` 解析 #标签）→
  toast 反馈 → 自动收起。mock 后端模式走既有 api-shim，同样可用。
- **快速入口 / 设置**：面板内静态入口列表 → emit `navigate` 事件（复用
  本次 `NavigateBridge`，载荷校验沿用 `sanitizeNavigatePath`）→ 主窗口
  路由跳转并展开面板收起。
- **快捷键兜底**：注册全局快捷键（候选 ⌥Space / ⌘⇧M）直接 toggle
  notch-panel，与托盘「打开速记」行为归一。
- **预计工作量**：Rust 窗口管理 + hover/blur 状态机 1 天；panel 前端 UI
  （textarea + 入口列表 + toast）1 天；边界情况打磨 1 天。

## 4. 边界情况

1. **全屏应用**：全屏 space 在刘海窗口之上，trigger 不可见（系统限制）。
   接受现状：全屏时用快捷键兜底；不尝试注入他人全屏窗口。
2. **多显示器**：v1 只跟主显示器（刘海物理上只存在于内建屏）；外接屏
   顶部不显示。
3. **无刘海 Mac / 外接屏**：检测 `NSScreen.safeAreaInsets.top > 0` 判定
   有无刘海；无刘海时 pill 悬浮在顶部居中（同位置，观感略突兀，可设置
   关闭 trigger 只留快捷键）。
4. **误触**：hover 展开**只**展开 trigger（胶囊微加宽），面板需 hover
   停留 ≥150ms 或点击才展开，避免划过顶栏就弹。
5. **系统「隐藏刘海」设置 / 缩放分辨率**：位置计算基于 `primary_monitor()`
   的实际几何，不写死坐标；展开后窗口不得覆盖菜单栏交互区（鼠标事件
   透传菜单栏）。
6. **自动隐藏**：失焦、Esc、保存成功均收起；收起后 trigger 回到胶囊态。

## 5. 验收标准（原型阶段）

- [ ] 有刘海 MacBook 上：胶囊贴合刘海下缘，hover 停留弹出面板，Esc /
      失焦 / 保存成功收起。
- [ ] 面板输入 Enter → 速记出现在 `/memos`（含 #标签解析），无需打开主窗口。
- [ ] 面板快速入口点击 → 主窗口跳对应页面。
- [ ] 全局快捷键可唤出/收起同一面板。
- [ ] 主显示器分辨率变更 / 接拔外接屏后 trigger 位置仍正确或自动隐藏。
- [ ] 普通浏览器 / PWA / 移动端完全不受影响（所有新代码 Rust 侧 + tauri
      平台判定内）。

## 6. 待讨论原型问题清单

1. 展开触发：hover 停留时长（150ms?）还是 hover + 点击两级？误触阈值接受多少？
2. 面板尺寸与信息密度：360×480 是否合适？要不要最近 3 条速记预览？
3. 动画：展开用淡入 + 下滑（180ms）还是无动画求稳？
4. 胶囊观感：纯色块模拟刘海，还是胶囊上加极淡的图标/文字提示可交互？
5. 快捷键选型：⌥Space（抢系统聚焦搜索风险）/ ⌘⇧M / 其他？
6. 无刘海 Mac 的策略：悬浮 pill 显示 / 只留快捷键 / 设置项让用户选？
7. 面板里除了速记 + 入口，要不要放「今日待办预览」（依赖任务域接口）？
