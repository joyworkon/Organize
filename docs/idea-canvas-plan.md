# 构思画布：产品方案与实施规格

> 日期：2026-09-20。状态：规划完成，尚未实现。
> 仓库核对基线：`master@bae941a`。本文件仅定义本次新功能，不替代总路线图。
> 用户目标：在无限画布上，通过输入和少量加号操作，快速搭建海报、内容卡片、演示页面等想法原型；后续持续扩展。
> 本文中的尺寸、快捷键细节和分期是建议默认值，供执行 Agent 直接落地；不是声称用户已经逐条确认。原始交互需求优先保留。
> 执行提示词见 [idea-canvas-agent-prompt.md](./idea-canvas-agent-prompt.md)。

## 1. 定位、名称与入口

推荐名称：**构思画布**。一句话介绍：**把想法写下来，让版式自己长出来。**

它结合无限画布的空间感、表格的对齐能力、演示页面的视觉表达。核心价值是先输入内容，再自动形成有秩序的版面。第一版服务内容原型，不承诺专业印刷或 PowerPoint 文件兼容。

| 候选名 | 优点 | 局限 |
| --- | --- | --- |
| 构思画布（推荐） | 说明用途，能涵盖海报、演示和方案原型 | 侧栏占四个字 |
| 画布 | 简短，用户容易识别 | 未体现自动排版特点 |
| 灵感板 | 亲切，适合收集素材 | 容易被理解为素材收藏板 |
| 拼页 | 有辨识度，强调模块组合 | 首次使用需解释，也偏向单页 |

桌面一级导航在「笔记」之后、「待办」之前增加「构思画布」，与笔记同级，不放进笔记子页面树。新功能路由统一用 `/canvas`，实体统一用 `CanvasDocument`，避免将来中文改名影响路由和存储。

- `/canvas`：画布文档列表，支持新建、重命名、复制、软删除，按最近修改排序。
- `/canvas/[id]`：一个无限工作空间，可容纳多个自动版面及自由容器。
- 命令面板提供「打开构思画布」「新建构思画布」。全局内容搜索接入放到后续版本。
- 移动端从现有侧栏抽屉进入，不将现有五个底栏入口扩成六个。详情隐藏底栏，提供返回列表、预览、缩放。第一版手机只读预览，编辑明确提示在桌面进行。
- 沿用现有主题、按钮、图标系统。无限画布是内容区域，应用导航仍保持统一。

## 2. 用户心智：工作空间 → 版面 → 模块

| 层级 | 用户看到的对象 | 负责的事情 |
| --- | --- | --- |
| 无限画布 | 整个工作空间 | 平移、缩放、放置多个方案 |
| 自动版面 | 一张会向下生长的稿子 | 固定设计宽度，维护内部行列布局 |
| 模块 | 标题、正文、图片等容器 | 承载内容、样式和局部编辑 |
| 自由容器 | 可任意摆放的文本或图片 | 绝对定位，不参与自动行列排版 |

首个双击动作会同时创建版面及一个标题模块。版面外框仅在选中或悬停时强调，不要求用户先理解层级、先画框再输入。

新建版面默认外宽 **640 个画布单位**，内边距 24、模块间距 16；画布单位在 100% 缩放时对应 CSS 像素。默认标题模块铺满版面内容宽度，之后新增的行也沿用这个内容宽度。版面高度随内容增长。

工作空间可缩放，但版面不会随浏览器窗口变窄而重新排版；手机查看缩放适配。调整版面自身宽度才会触发排版变化。

## 3. 冻结核心交互

### 3.1 创建与输入

1. 双击画布空白处，在指针世界坐标处建立版面，标题输入立即聚焦。
2. 双击现有模块只进入编辑，不创建重叠版面。工具栏也有「新建版面」入口。
3. 单击选择模块；拖模块操作柄才进行布局操作，选择文字不能意外拖动画布。
4. 首块默认标题样式，后续默认正文样式，均可切换。第一版文本支持纯文本、换行、字号档位、字重、颜色和对齐；不要求复刻完整笔记富文本编辑器。

### 3.2 Enter：在当前整排下方新增通栏

把一排左右并列的列及列内所有上下模块称为一个「分区」。Enter 的插入锚点是这个分区，而不是当前模块的屏幕下边缘。

- 单列时：在当前分区后新增一个单列分区。
- 双列或更多列时：在整个分区之后新增一个通栏分区，宽度与版面内容区域一致。
- 即使当前模块位于某一列的第二层，Enter 仍在所属分区之后新增通栏，不插进相邻列中间。
- 原分区之后已有内容时，新分区插在二者之间，已有内容顺延；同一版面内不重叠。
- 新模块获得焦点；新增通栏默认正文样式。
- `Shift+Enter`：当前模块内换行。粘贴多行文本也保留在当前模块，不把每行意外拆成容器。
- 光标位于文本中间时，Enter 把后半段文本移入新通栏；有选区时以选区起点拆分，选区及其后文字均迁移，不静默丢字。
- 中文输入法组合期间，Enter 只确认候选词；必须处理 `isComposing`，并验证浏览器组合事件时序。
- 允许连续 Enter 创建空模块，便于搭骨架；每次均可撤销。

```text
初始                      在 B 中按 Enter
┌─────────────────┐       ┌─────────────────┐
│       标题       │       │       标题       │
├────────┬────────┤       ├────────┬────────┤
│   A    │   B    │   →   │   A    │   B    │
└────────┴────────┘       ├────────┴────────┤
                          │   新通栏模块 C   │
                          └─────────────────┘
```

### 3.3 左右加号：给当前分区增加一列

- 悬停或键盘选中模块时，在所属列的左/右边缘显示加号；点击后在该列左/右加入一个新列，列内含一个空模块并聚焦。
- 新增的是当前分区的列，不改变上方标题或其他分区的列数。
- 新列出现后所有列重新分配现有宽度，版面总宽不因文字长度增长。默认文本列等分，长内容换行、增高。
- **首版边界**：若当前列已有上下多个模块，左右加号仍添加贯穿当前分区的新列。悬停预览应画出整列范围，避免用户以为只分割一个小块。任意单块再嵌套横排放到后续版。
- 每列最小外宽建议 120。添加后无法满足最小宽度时禁用加号，提示加宽版面；不能暗中扩宽整张稿子。用户可调整版面宽度或列分隔线。

### 3.4 模块底部加号：只在当前列向下新增

- 模块底部中心的加号，含义为「在本列下方添加」。在当前模块后面插入新模块，不创建通栏。
- 同一列内部模块默认等高：根据其中最高的内容需求分配高度；其他列的模块随整排高度伸展。
- 另一列只有一个模块时，它占满整排高度，呈现类似跨行合并单元格的效果，但不用实现电子表格的合并操作。
- 整排外侧另设「添加通栏」入口，其效果与 Enter 相同；两个底部入口的位置、提示和插入预览必须区分。

```text
初始                      点击 A 底部的局部加号
┌────────┬────────┐       ┌────────┬────────┐
│   A    │   B    │       │   A    │        │
└────────┴────────┘   →   ├────────┤   B    │
                          │   C    │        │
                          └────────┴────────┘
                          A 与 C 等高，B 占满两层及中间间距
```

如果随后给 B 底部加一个 D，则恢复为左右各两块；两列总高一致。删除 C 后自动回收多余高度，B 恢复与 A 等高。这里的边框仅为示意，成品模块可无边框。

### 3.5 自由容器

- 工具栏提供「自由文本」「自由图片」，创建后可拖动、调整宽度及层级。
- 首版使用世界坐标，独立于版面；不参与自动增高，不会把其他模块挤开。Enter 在自由文本中正常换行。
- 选中时标识「自由定位」，以免用户期待它自动对齐。
- 首版不做自动模块与自由模块的无损互转，也不做跨版面拖放；避免拖一下就破坏结构。
- 自由容器不会因为视觉上重叠某版面就自动属于该版面。后续导出单个版面时，需要明确将自由元素附着到版面的动作。

## 4. 自动排版规则

### 4.1 宽度、高度的计算顺序

布局必须遵循「先确定宽度 → 测量内容自然高度 → 算分区高度 → 拉伸容器」的单向流程。

1. 版面固定宽度减去内边距，得到各分区的内容宽度。
2. 分区减去列间距后按比例分列，列宽总和与间距之和严格等于分区宽度。
3. 按最终列宽测量每个模块的自然高度，计入模块内边距、文本换行、图片原始比例及最小高度。测量不使用已经 stretch 的容器高度。
4. 对某列，若模块数为 `n`、其中最大自然高度为 `m`、纵向间距为 `g`，则等高所需列高为 `n*m+(n-1)*g`。
5. 分区高度 `H` 为所有列所需高度的最大值；各列模块实际高度为 `(H-(n-1)*g)/n`。因此有两块的列内部等高，有一块的列自然跨两层。
6. 下方分区依次顺延，版面总高累加。不同版面维持各自世界坐标，版面增长不会自动推动旁边的其他版面。

模块高度默认由内容驱动，不做固定高度截断；长 URL 等不可断字符串必须可折行。后续可增加列内非等高权重，但不要让首版新模块随机分到不同高度。

### 4.2 图片与文字自适应

图片必须保存 `naturalWidth`、`naturalHeight`，读取成功后比例 `r=naturalWidth/naturalHeight`。文件尚未解析时显示占位，解析/上传成功后才参与最终排版。

**容器等高不代表图片变形。** 默认「完整显示」（contain）；可手动切换「铺满裁切」（cover）。禁止直接拉伸图片宽高以填满非同比例容器。

- 单列图片：利用可用内容宽度与原始比例计算自然高度。
- 文本 + 图片双列：提供默认开启的「智能比例」，同时保留「等分」「自定义比例」。
- 智能比例建议确定性算法：先在等分参考宽度测量文字自然高度 `T`；以 `r*T` 作为图片内容期望宽度，加回图片模块内边距后，将图片列外宽约束在可分配列宽总和的 25%–60% 之间，并满足双方最小列宽；余宽给文字。随后按最终宽度重测文字与图片高度，用二者最大值确定分区高度。
- 上述算法只作一次参考测量和一次最终布局，不能用拉伸后的图片高度反推图片宽度，避免宽高相互追逐。
- 插入/替换图片或更改版面宽度时重算；文本编辑期间宽度保持稳定、只更新高度，结束编辑后再重算智能比例。拖动列分隔线后切为自定义比例，不再被自动计算覆盖；用户可恢复智能比例。
- 图片较高：文字容器同步拉高，文字字号和行高不变，默认顶部对齐。
- 文字较高：图片容器同步拉高；完整显示可留白，铺满裁切可以裁掉局部，二者都不变形。
- 智能比例首版仅覆盖「两个列、每列一个模块、一文一图」。多列或列内多层采用等分/手动列宽，仍按图片比例和内容高度拉伸。这是明确的渐进增强边界，不应偷偷承诺任意复杂布局都自动求最优比例。
- 图片加载失败保留尺寸占位并提供重试/替换，不能将整列折叠到零高。

### 4.3 可预测性优先

- 调整列分隔线只改变本分区，不改变标题宽度。
- 拖动版面边缘才改变整张版面的设计宽度。
- 调整字体或内容可增高，不能缩小字号来强塞内容。
- Hover 加号和选择边框不参与布局计算，缩放后点击区域仍保持可操作大小。
- 加号先显示半透明插入预览，点击才提交；一次操作就是一个可撤销事务。

## 5. 首版界面与范围

列表空态直接展示「新建构思画布」，并用一句提示介绍双击输入。不用先弹尺寸向导。

详情顶部：返回、文档名称、保存状态、撤销/重做、预览。左侧小工具条：选择、新建版面、自由文本、自由图片。右侧按选中对象显示紧凑属性栏；底部右侧提供缩放、100%、适合全部。

| 首版必须交付 | 后续增加 |
| --- | --- |
| 文档列表及真实保存；删除可恢复 | 共享、评论、多人实时协作 |
| 双击创建、Enter 通栏、左右增列、局部下方加块 | 任意层级嵌套、跨版面拖放、复杂合并拆分 |
| 等宽/自定义列宽、一文一图智能比例 | 智能布局建议、更多内容权重策略 |
| 文本、图片、自由容器 | 笔记/稍后读引用、视频、链接卡、形状和连线 |
| 基础颜色、字重字号、对齐、间距、背景、圆角 | 模板市场、品牌主题、细致排版控制 |
| 缩放、平移、拖版面、预览、撤销/重做 | 小地图、多选框选、吸附参考线 |
| 草稿恢复、冲突保护、mock 演示与测试 | 跨设备离线队列、历史版本 UI |
| 全局备份/恢复与垃圾箱接入 | PNG/PDF/SVG 导出、逐版面演示 |

PNG/PDF 是首版后的第一个增量：需要明确导出对象、字体/图片加载、跨域图片及自由元素归属，不要先放一个不可用的导出按钮。原始诉求是快速搭建想法，首版先把结构编辑和预览闭环做扎实。

## 6. 技术设计建议

以下是基于当前仓库的实施建议，不是对外部库版本的判断。执行时若选择新增第三方库，应另行核对其官方文档和授权。

### 6.1 独立数据模型，DOM 渲染

采用 React + DOM/CSS Grid/Flex 实现版面内部布局，用工作区容器的坐标变换实现平移缩放。复用现有 Zustand、主题和 UI 组件，不要求一开始引入大型白板引擎。

不要把画布树塞入 `notes.content`，不要让普通笔记编辑器承担整个无限画布。首版文本可使用受控 textarea 加非编辑态文本渲染，后续在文本模块内部独立接入轻量富文本。

建议文档结构（概念结构，不要求逐字照抄类型）：

```text
CanvasDocument { schemaVersion: 1, boards: Board[], freeItems: FreeItem[] }
Board { id, x, y, width, padding, gap, style, sections: Section[] }
Section { id, widthMode, columnWeights, columns: Column[] }
Column { id, blocks: Block[] }
Block = TextBlock | ImageBlock
TextBlock { id, type: "text", text, role: "title" | "body", style }
ImageBlock { id, type: "image", asset, naturalWidth, naturalHeight, fit, style }
FreeItem { id, x, y, width, zIndex, block: Block }
```

所有对象拥有稳定 ID。自动模块不持久化 x/y 或 DOM 测出的高度；只存语义结构、宽度策略与样式。自由图片高度由宽度及图片比例计算，自由文本高度由内容计算。首版自由容器宽度可调，高度自动增长。

文档结构版本与数据库修订号分开：`schemaVersion` 负责升级，`revision` 负责并发。对未来未知块不能静默删除，应保留原数据、展示占位并防止不兼容保存。

操作封装为纯命令，例如 `createBoard`、`insertSectionAfter`、`insertColumn`、`insertBlockBelow`、`splitTextToSection`、`deleteBlock`、`resizeBoard`。命令同时返回新的文档和焦点目标。保存、上传不进入 reducer 或状态更新器。

删除最后一个块时移除空列，移除最后一列时移除空分区；若版面因此为空，保留一个可输入的空块。删除整个版面只能通过版面操作。结构整理不得改写剩余对象的 ID。

### 6.2 坐标、输入和历史

- 坐标换算必须扣除画布视口的真实边界：`world=(client-viewportOrigin-pan)/zoom`；侧栏、页头偏移不能写死。
- 空格+拖拽或中键平移，触控板滚动平移；Ctrl/Meta+滚轮缩放，围绕指针位置保持世界坐标不变。缩放建议 10%–400%。
- 文本编辑时不拦截空格、方向键、删除和正常选区；只对已定义的结构 Enter 做处理。键盘快捷键按焦点范围注册。
- 历史统一记录文本与结构变化，避免 textarea 原生撤销与文档撤销互相打架；连续文字输入合并为一个短事务，IME 合成一次提交，拖动从按下到松开为一个事务。
- 上传完成回调必须检查文档身份、模块 ID 和上传 token，已删除/撤销的模块不能被异步回调复活。
- 活跃文本模块不得在每次击键后卸载重建。ResizeObserver 只触发必要测量，不能进入尺寸反馈循环。
- 用页面级懒加载加载画布功能，不让其他导航页面承担画布编辑器开销。

### 6.3 存储与权限

新增 `canvas_documents` 表，建议字段：`id uuid`、`user_id`、`title text`、`content jsonb`、`revision bigint`、`created_at`、`updated_at`、`deleted_at`。图片沿用现有上传链路，content 保存可恢复的资源地址/标识和尺寸，不保存短期 object URL。

- 表必须启用按用户隔离的 RLS，并显式 GRANT 所需表级权限。首版仅所有者可见，不复用笔记协作角色假装支持共享。
- 接口建议：`GET/POST /api/canvases`、`GET/PATCH/DELETE /api/canvases/[id]`。列表只读元数据，不拉取所有大 JSON。
- PATCH 必须基于 `expectedRevision` 原子比较并递增，可用有严格权限校验的 RPC 实现；不能先查询再无条件覆盖。删除/恢复也参与修订号，避免迟到保存恢复已删除内容。
- 客户端生成 UUID，新建重试需幂等；不同用户已有的相同 ID 不得泄漏存在性或被覆盖。用户身份取服务端会话，不信任传入 user_id。
- 非法结构、重复 ID、非有限坐标、不支持类型、无效权重、过大内容和过多节点均在服务器验证；客户端同一契约先行检查。
- 迁移编号按执行时仓库最大值递增。核对基线已有 083，不能照旧说明写 079 或盲目锁死下一个编号。

### 6.4 自动保存与恢复

- 停止编辑约 800ms 后保存，单文档请求串行，后续编辑合并进最新待保存快照；旧响应不得将新内容标记为已保存。
- 显示「保存中 / 已保存 / 仅保存在本机 / 保存失败 / 存在冲突」。只有服务端确认对应修订才显示云端已保存。
- IndexedDB 草稿以登录用户及文档 ID 隔离，保存文档、基础修订号与本地更改序号；关闭/刷新后可恢复，登出或切账号不混用草稿。
- revision 冲突时暂停自动写回，保留本地内容，提供查看远端和将本地内容保存为独立副本。首版不自动合并结构树、不无提示覆盖远端。
- 恢复草稿遇到远端已删除/无权限，不自动复活原文档；可将仍有权保留的本地内容另存为新文档。
- 真实上传失败保留预览和待重试状态，明确图片未上传，不能把 blob URL 当成已保存资源。需恢复的待上传文件放在按账号隔离的本机存储中。
- mock 增加表、API shim、修订冲突与错误路径。mockDb 仍是内存，不可宣称刷新后云端保存；可用同一草稿机制恢复本机示例，并显式标明演示模式。
- mock 图片使用有体积限制的本地资源适配器/IndexedDB，刷新可重建 URL；真实线上不把大 base64 塞进 content。图片未持久化时给出准确状态。

建议测试分配：Vitest 覆盖命令、尺寸、校验、历史、草稿和保存状态；Playwright 覆盖缩放坐标、真实排版边界框、输入焦点和关键 E2E；数据库验证覆盖用户隔离、CAS 原子性与垃圾箱/备份 RPC。CSS 等高不能只依赖 JSON 快照验证。

完成后运行 `pnpm --filter @organize/web typecheck`、`pnpm --filter @organize/web test` 及新增画布相关 E2E。若环境缺少 Supabase、浏览器或构建条件，列出未验证项与原因，不把 mock 通过当真实数据库验证。

产品验证目标（是目标，不是测量结论）：

- 首次用户无需理解行列模型，即可在 3 分钟内搭出「标题 + 左文右图 + 通栏说明」。
- 上述骨架创建过程中不必手动计算模块尺寸或对齐坐标。
- 同一操作序列在刷新后恢复为相同结构，图片、文字无截断或意外丢失。
- 桌面基准样例为 5 个版面、合计 200 个模块；记录设备、浏览器和操作延迟，目标输入与结构操作的可见反馈 P95 小于 100ms。未达标时先分析测量/重渲染，不提前引入复杂虚拟化。
