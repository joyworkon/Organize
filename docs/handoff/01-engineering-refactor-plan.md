# Organize 工程重构执行计划

日期：2026-09-05；基线 d9ec06e；先读 `00-交接与执行顺序.md`。下文路径相对仓库根目录。文件名是定位入口，行号可能变化，以实际函数为准。

## A. 总体决策

保留 Next.js、React、TipTap、Supabase、pnpm monorepo。保留现有文档 JSON、块 id、任务 id、RPC 与 CRDT 基础。此次不换框架、不升级 TipTap、不建通用低代码平台，不把所有查询改成一套新 API。

顺序是：可靠性修复 → 同行为职责拆分 → 关联数据能力。禁止同时修改保存协议和页面布局。旧迁移不可编辑；新迁移编号执行时检查最新文件后确定，不能固定假设下一份仍是 073。

### 不得破坏的约束

1. 文章收集仍统一走 `lib/reading/collect.ts` 的 collectReadingItem。
2. 笔记正文保持现有 TipTap schema 和稳定块 id，历史笔记不批量重新生成 id。
3. 保存保持 revision、mutation id、串行排空、事务来源分类；viewer 不写入。
4. owner/editor/viewer、匿名公开编辑、协作启用/关闭/断开，都必须显式覆盖。
5. 任务状态副作用不进入 React state updater；任务与正文原子保存不能拆成两条独立请求。
6. 页面显示属性、标签、来源引用不能因重构消失；旧 URL 和查询参数保持可用。
7. 新表有 RLS 和 GRANT；服务端授权不能依赖浏览器角色判断。
8. 不靠隐藏报错实现降级。mock、真实后端、离线的能力差异必须可见。

### R01 Markdown 导出正文完整性

### R02 导出当前编辑快照

定位：`app/(main)/notes/[id]/page.tsx` 的 exportMarkdown/draftRef、`components/share/export-button.tsx`。

决定：编辑页导出点击瞬间的本地快照，笔记卡片导出服务器已保存版本。编辑页导出不依赖网络保存成功。

步骤：

1. 将“获取数据”与“渲染并下载”拆开；后者接收 title/content 快照，放在 lib/export，不让核心库依赖 React 组件。
2. 编辑页捕获完整快照再 await；不要在异步完成后读切换到另一笔记的 refs。
3. 卡片仍按权限读取数据库。导出函数必须 await/catch，失败恢复按钮，不产生未处理 rejection。
4. 导出成功只说明下载已触发；有本地未同步内容时提示“已导出当前内容，云端仍待同步”，不修改 dirty 状态、不清草稿。
5. 把 R01 的降级信息以简短提示呈现，不阻塞可读导出。

验收：离线编辑后导出包含最新字；保存冲突时导出包含本地字；下载不清冲突状态；快速切页不导错笔记；卡片网络失败有反馈；中文/非法文件名处理保持。

### R03 本地草稿失败必须可见

定位：`lib/notes/local-draft.ts`、`app/(main)/notes/[id]/page.tsx` 的 persistCurrentDraft/queueSave/冲突提示。

决定：本卡只补真实性，不立刻迁移 IndexedDB。

步骤：

1. 为草稿写入定义有类型结果，如 ok / quota / unavailable / serialization；分类未知异常时保守标 unavailable。
2. 调用处消费结果，保存会话记录本地持久化是否成功。服务器正常保存成功时可清该笔记提示。
3. 失败时继续允许编辑和正常服务器保存，但展示持续提示：“本机草稿未能保存，请导出当前内容或保持页面打开”。提供 R02 导出入口。
4. 修改所有“已保存在本地”“草稿已保留”文案，必须依据实际写入结果。
5. 页面有仅内存修改时使用标准 beforeunload 提醒；它只是辅助，不声称手机关页一定能拦截。

验收：注入抛 QuotaExceededError 的 storage、不可用 storage、成功 storage；失败不崩溃、不谎称已保留；云端保存成功正常清 dirty；账号和 noteId 键隔离保持。禁止 catch 后返回伪成功。

### R04 同步块正确判定成功并减少无效事务

定位：`components/editor/extensions/synced-block.tsx`、`synced-block-client.ts`、`app/api/synced-blocks/[id]/route.ts`。

步骤：

1. GET/PATCH 先判断 HTTP 状态，再验证响应形状。401/403/404/409/500 或坏 JSON 都不进入成功分支。
2. 维护 loading/dirty/saving/saved/error 状态。失败保留待写快照、显示块内重试；仅服务器确认成功后广播。
3. transaction 先检查 docChanged，再比较目标块前后内容；光标移动、选区变化、其他块变化不发 PATCH。
4. 替换远端内容使用明确事务 meta：`transactionSource=remote-sync`、`addToHistory=false`，并带同步块来源标记；监听器识别该标记，不回写同一消息。
5. 比较内容一致时不 dispatch。广播附 origin/session 标识和单调本地序号，忽略自己的消息；不要用“1 秒内都忽略”代替来源识别。
6. editable=false 时不发写请求；服务端权限继续执行，前端只读不是授权依据。

验收：选区移动和编辑其他块发 0 次 PATCH；一次块内容修改只产生一次防抖请求；500 不广播、不显示已同步；成功才广播；两个本地实例不无限互传；viewer 浏览不写入。

本卡不声称跨设备冲突已解决，待 R05。

### R05 同步块重开、离线、并发完整性（独立设计后实现）

定位：R04 文件、synced_blocks 实际迁移与权限、备份 schema/restore、mock/api-shim。先查清当前权限和 backup 是否包含同步块，缺口单独列明。

发现：hydrated 是文档持久化属性，保存为 true 后下次打开可能跳过拉取；同浏览器广播不等于跨设备同步；组件卸载清 timer 不等于已提交；独立块保存不受页面保存承诺自动覆盖。

建议最小协议：

1. hydrated 改为组件会话状态，不以旧文档 true 判断“本次已从服务端加载”。兼容读取旧属性但忽略其网络可信性，不批量改 JSON。
2. 加载期间保留可读快照；有本地未同步变更时不无条件用服务器覆盖。请求返回前已编辑时进入合并/冲突路径。
3. 每个 syncedId 串行写，保存中后续编辑排队；用账号+syncedId 保存待同步快照。块卸载、切页、刷新后不丢 pending。
4. 并发采用服务端原子 revision 比较或明确的同等协议，不能先 SELECT 后无条件 UPDATE。重复请求有幂等标识。
5. 冲突保留双方内容，提供刷新远端、保留本地副本等确定行为；默认不覆盖远端。
6. 跨设备更新：使用已有可用订阅，或活跃页面的可见性驱动重验证；重连和窗口聚焦重新检查。不把 BroadcastChannel 写成跨设备能力。
7. 集成到页面保存摘要：块未同步时页面不得笼统显示“全部已同步”。若需要接入 R07，先暴露独立块状态接口，后续再汇总。
8. mock 按同样返回形状实现；数据库变更新增迁移，补 RLS/GRANT、RPC、回填和备份字段兼容。

验收矩阵：两账号授权/无权；两浏览器同时改；离线→改→关页→重开→联网；保存响应丢失重试；删除块/撤权；旧 JSON 的 hydrated=true；A 笔记与 B 笔记引用同块；服务器错误不丢本地内容。

停止条件：无法证明 revision 检查原子性、不能运行真实服务验证时，标为待验证，不合并成“同步已完善”。禁止自行用 CRDT 重写整个同步块系统。

### R07 抽离笔记保存会话（先测试，后移动）

定位：`app/(main)/notes/[id]/page.tsx`、`lib/offline/note-sync.ts`、`lib/notes/local-draft.ts`、`hooks/use-note-collab.ts`。

目标：页面不再直接编排 dirty/revision/mutation/重试；抽取到建议的 `hooks/use-note-session.ts` 与 `lib/notes/note-save-session.ts`。文件名可调整，但职责和接口不能模糊。

步骤：

1. 画出现有加载、编辑、排空、冲突、恢复、离线创建、切页、卸载时序，写行为测试后再搬代码。
2. 为每个会话固定 accountId+noteId+generation。旧请求回调不能更新新会话状态，旧 finally 不能清新保存锁。
3. 保存核心注入 transport、draftStorage、clock、事件回调，不访问 DOM；React hook 只连接生命周期/状态，不另造一套保存算法。
4. 保持 role 到 RPC 的现有选择和 collab active 判定，不改变期望 revision=null 的既有分支语义。CRDT 断线/恢复是测试项，协议问题另开卡。
5. 统一 UI 状态派生，不用 saving/offlinePending/error 三个互不约束的 flag 拼文案。可用 states：loading/clean/dirty/saving/local-only/conflict/error/read-only，加 localPersistence 和 childBlockStatus；具体状态图写入代码说明。
6. 快照复制、幂等 id、失败分类、串行排空保留；同批次重试复用 id，不同快照不得复用。
7. 对外提供 patchDraft、flush、retry、exportSnapshot、restoreDraft、resolveConflict；flush 返回类型化结果，不只 boolean。页面不要直接改会话内部 refs。
8. 先接旧页面，不改视觉。删除被替代的旧保存路径，避免双定时器、双 online listener、双写。

关键行为测试：

- 编辑 A，A 请求未返回时切 B 并输入；任何 A 回调都不能污染 B。
- 保存中继续输入：前一次响应不能清掉后一次 dirty，最终内容完整。
- 网络响应丢失：同 mutation 重试不会多建版本或假冲突。
- 冲突时不自动覆盖；副本、远端恢复行为明确。
- 离线创建先创建再更新；离线已有笔记不可读的既有边界不被误改。
- 恢复历史后卸载不把旧草稿写回。
- viewer 不写；角色撤销返回失败后停止写入。
- hydrate/remote-sync 不触发用户任务 mutation，手动修改仍触发。
- React 重挂载不双重保存；监听器与 timer 正确清理。

验收：页面只消费会话接口；上述测试和真实协作相关 E2E 通过。无需为了行数把逻辑拆成几十个碎片。

长期交付 R10b：文档链接索引。先确认已有表/函数是否可复用，再新增，避免重复索引体系。

### R12 大笔记性能与持久化升级（测量后实施）

定位：local-draft、note session、上传模块、图谱查询、笔记树加载。

先采样：1千/1万/5万中文字，分别带 0/10/30 图片；记录键入期间序列化次数、主线程长任务、保存请求数、初次打开时间、草稿大小。注明机器和浏览器，不能凭感觉承诺性能倍数。

如果全量 JSON 同步写 localStorage 确为瓶颈：

1. 保留立即内存快照；实现异步 IndexedDB storage adapter，短节流、串行提交、版本序号防旧写覆盖新写。
2. 用户+笔记隔离。异步持久化未完成时不显示本机已保存；pagehide 的尽力 flush 不是保证。
3. 旧 localStorage 草稿双读兼容；只有新写入与读回校验成功后清旧副本；升级失败保留旧数据。
4. 大图片不再无条件 base64 塞正文：待上传 Blob 存本机，上传完成替换正式引用；有明确大小限制、失败反馈和恢复策略。现存 base64 仍可读、可导出，不批量破坏迁移。
5. 不把 Y.Doc、正文快照和本地缓存重新设计为三个互相竞争的真相源。

如果主要问题是列表/关系拉取：改分页和复用查询，先定义一致性，再引入缓存。不得一上来加新全局状态库。

验收：相同样本对比前后数据；刷新/崩溃恢复、乱序写入、切账号、配额失败、升级失败都能保留可恢复内容；不以减少可靠性换取输入速度。
